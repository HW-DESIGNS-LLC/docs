ESPHome · Home Assistant

Your board in Home Assistant

Install ESPHome from this page and Crescent City becomes a Home Assistant device: battery level, USB power, the BOOT button and the RGB LED show up as entities, plus indoor temperature and humidity with an optional Qwiic sensor (not included). The OLED keeps showing the time, the temperature and the battery.

Installing from this page needs Chrome or Edge on a computer. You can still set it up with ESPHome Builder — see Using ESPHome Builder below. Installing needs a secure (https) connection to this page. View the YAML ↗

You need: Chrome or Edge on a computer · a data USB‑C cable · a 2.4 GHz Wi‑Fi network

Config 1.1.1 · ESPHome 2026.10+ · Home Assistant · board V1.0 and V2.0

Install

Install in three steps

About two minutes, with nothing but a browser.

  1. 1

    Plug in and click Install ESPHome

    Connect the board to your computer with a data USB‑C cable, open this page in Chrome or Edge and click Install ESPHome. Pick the board’s USB port, confirm, and leave the box ticked to erase the board on a first install. Installing takes about a minute.

    This replaces the Weather Clock. You can put the Weather Clock back at any time — see Help.

  2. 2

    Connect it to your Wi‑Fi

    When the install finishes, choose Connect to Wi‑Fi and enter your network and password.

    No computer at hand later? With no saved network the board opens a setup hotspot called Crescent City. Join it from your phone and pick your network on the page that opens. Use a 2.4 GHz network.

  3. 3

    Add it in Home Assistant

    Home Assistant finds the board by itself: go to Settings → Devices & services, look for Crescent City followed by six characters under Discovered and click Add. The clock on the OLED starts as soon as Home Assistant is connected.

    Not listed after a minute? Click Add integration, choose ESPHome and enter the IP address from the board’s status page (press BOOT). Leave the port at 6053.

Using ESPHome Builder

Take over a board you installed from this page

To change the configuration or update over Wi‑Fi, open ESPHome Builder: the board appears as Discovered. Click Adopt, then Install. Builder keeps your copy linked to the published configuration.

Or set it up from ESPHome Builder instead of this page

  1. In ESPHome Builder click New device, give it a name, choose ESP32‑S3, and skip the first install. Open Edit and replace everything except the api: block with: 
    substitutions:
  name: crescent-city
  friendly_name: Crescent City

packages:
  hwdesigns.crescent-city: github://HW-DESIGNS-LLC/docs/firmware/esp32-s3/esphome/crescent-city.yaml@main

esphome:
  name: ${name}
  name_add_mac_suffix: false

wifi:
  ssid: !secret wifi_ssid
  password: !secret wifi_password
  2. Click Install and choose the USB option. After that, updates go over Wi‑Fi. Then add the device in Home Assistant as in step 3. If the port doesn’t appear, hold the BOOT button while plugging the board in.

What you get

In Home Assistant and on the screen

  • Battery voltage and level
  • Charging state and USB power
  • BOOT button and RGB LED, for your own automations
  • Indoor temperature and humidity with a Qwiic SHT4x sensor on the side connector (sensor not included)
  • Clock and status pages on the OLED — press BOOT to switch

Battery

Running on a battery

While USB is plugged in, none of this applies.

Not verified with ESPHome yet

Battery life: Home Assistant needs the board to stay connected, so ESPHome keeps Wi‑Fi on and you should expect a shorter battery life than with the Weather Clock. Not measured for ESPHome yet; for comparison the Weather Clock with Wi‑Fi always on draws ≈70 mA, about 14–14.5 hours per 1000 mAh.

Low-battery shutdown: the ESPHome configuration uses the same thresholds and behaviour as the Weather Clock, but this has not been verified on hardware yet. The 0.78 mA sleep current and the 19 of 19 USB wakes were measured with the Weather Clock.

How the configuration protects the battery (the same settings as the Weather Clock):

Nearly empty
3.45 VwarningThe battery icon blinks with LOW, the status LED blinks red and Battery low turns on in Home Assistant.
Empty
3.30 Vshutdown“Battery low — charge me” for 10 s, then Wi‑Fi, the LED and the screen switch off and the board goes into deep sleep.
Back on
USB‑Cplug it inThe board wakes, starts normally and charges. To keep running on battery after a shutdown it needs 3.50 V.
Threshold details

All voltages are at the battery connector. The decision uses a 30‑second median, so a short dip during a Wi‑Fi burst can’t trigger it.

In deep sleep the board also wakes for a moment every 10 minutes to check for USB, as a backup for the USB wake. The Weather Clock measures 0.78 mA in this state.

After a shutdown the board keeps running on battery only once the battery is back above 3.50 V, so a short plug-in, or RESET on a still-empty battery, just shows the message again.

Turning the Low-battery shutdown switch off disables the warning and the shutdown — not recommended on a battery.

The battery icon while charging

While USB is plugged in, the battery icon shows the charging phase: bars run while charging, three bars with the fourth blinking while the charger tops off, four bars when it stops, or after 20 minutes if the charger stays idle (battery already full, or none fitted).

Customize

Make it yours

Adopt the board in ESPHome Builder (see Using ESPHome Builder under Install), then add a substitutions: block to your copy of the configuration and install.

Settings you can change
temp_unit"F" or "C" — OLED only; match your Home Assistant unit setting
outdoor_weather_entityweather.forecast_home — the weather entity for the outdoor temperature
friendly_nameCrescent City — the device name in Home Assistant
vbat_warn / vbat_cutoff3.45 / 3.30 — battery thresholds in volts (advanced)
substitutions:
  temp_unit: "C"
  outdoor_weather_entity: weather.home
Free pins for your own sensors

Free header pins for your own sensors and outputs: GPIO 1, 5, 6, 7, 13, 15, 16, 21, 35, 36, 37 and 39 — see the pinout. The Qwiic port takes more I²C sensors on the same bus.

Help

Common questions

The Install button doesn’t find the board

Use a data-capable USB‑C cable and Chrome or Edge on a computer. If the port still doesn’t appear, hold the BOOT button while plugging the board in, release it, and click Install again.

The clock shows --:--

The board takes the time and time zone from Home Assistant. It appears once the device is added in Home Assistant (status page: HA connected).

Outdoor temperature shows --

The board reads the temperature of weather.forecast_home, the weather entity Home Assistant creates for your home. If yours has a different name, set outdoor_weather_entity (see Customize).

Indoor temperature is unavailable

Indoor temperature and humidity need a Qwiic SHT4x sensor, which is not included with the board. Plug the sensor into the side connector and restart the board — ESPHome looks for the sensor at power-up.

How do I get the weather clock back?

Upload the weather clock sketch from the Arduino IDE, as in the getting-started guide. Its source is in the firmware folder.

Does it need Home Assistant?

For the clock and the outdoor temperature, yes. Everything else — sensors, battery, the setup hotspot — works on the board itself, and ESPHome devices can also be used without Home Assistant.
